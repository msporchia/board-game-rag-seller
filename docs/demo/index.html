One pipeline, three journeys

An embedding model turns a whole product record into one point in semantic space — a lossy centroid of whatever text you feed it. It's fixed and query-agnostic: it can only embed the text it's given. A real catalog mixes richly-described games with name-plus-a-few-fields ones, so fed raw, that difference silently becomes the ranking — well-documented games surface, thin ones vanish. Not relevance; a data-entry accident.

Every game must be equally findable and equally sellable, whatever the quality of its source data. If one game is to outrank another, it must be intentional — never inherited from data quality.

The embedder is fixed — the text is the lever. Three real games, carried end-to-end through the pipeline and ranked by the real retriever on a frozen 50-game corpus: same embedder, same queries, only the embedded text changes. Each journey demonstrates a different property of the same machine — including the one where it loses.
